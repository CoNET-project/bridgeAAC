# Audit record 2026-10-16

This record covers the internal review of `bridgeAAC` (findings H1, H2, M1–M6),
the fixes merged to `main`, the reproducible release build, and the production
switch to `bridge-aac-v0.33.12`. It does not change the custody state: custody
stays closed, the registry stays paused, and Shadow stays read-only.

## Findings and fixes

**H1 — Base L1 anchor did not bind the block to the output root.**
`BaseL1Finality::authenticate` accepted any Base block at or below the anchored
height, using execution-client values. It now:

- rebuilds the Base header RLP from the RPC block and requires
  `keccak256(header) == requested hash`;
- accepts only the block whose number equals the anchored game's L2 sequence;
- reads the message-passer account proof (`eth_getProof` for
  `0x4200000000000000000000000000000000000016`) and recomputes
  `keccak256(0x00…00 ‖ stateRoot ‖ storageRoot ‖ blockHash)`, which must equal
  the anchored root (see `src/base_output_root.rs`).

Blocks behind the anchor are refused until an ancestry proof is implemented.
This is a behaviour change: `check-header` and `verify-receipt` with
`--l1-rpc` accept only the anchored block.

**H2 — Genesis trust root was only a field inside the served state.**
The validators-root check alone did not identify the genesis state. The pin now
requires the genesis header root, the genesis state root, and the validators
root. The signing domain for sync-committee aggregates uses the pinned
validators root, not the copy served by the beacon. Two beacons agree with the
pinned constants (`genesis-pin yes`, `aggregate-verify yes`,
`signature-check yes`). The operator table in
`gitbook/developers/l1-independent-confirmation.md` lists `{HOST_H}` and
`{HOST_D}` as identities of the publishing operator, so under that
definition `{HOST_H}` is **not** an independent source. The H2
independence check therefore remains open (see Open items).

**M1 — Unsigned confirmations raised the checkpoint safety label.**
Confirmation files are unsigned, so counting their signer strings no longer
changes `safety`; such a checkpoint stays `observed`. The supermajority
checkpoint block is now checked with a BLS aggregate verification
(`sync_aggregate_binds`).

**M2 — `assess()` did not check the returned hash against the requested hash.**
`assess()` now returns `UnknownHeader` when `block.hash != requested header`.
Regression test: `a_substituted_block_does_not_authenticate_another_hash`.

**M3 — `settle` defaulted the Circle balance to `u128::MAX`.**
The default is now `0`, so a burn-release AAC stays reserved unless
`--circle-balance` is given.

**M4 — A missing shadow cursor was silent.**
A missing cursor file is reported as `cursor missing` and pages
`alert cursor-missing`. A fresh start still begins at the current finalized
head. The first run after a fresh deployment raises this alert by design.

**M5 — A cancellation in a later scan window was lost.**
`merge_op_note` keeps `executed` and `cancelled` sticky across scan windows.
Covered by the shadow-service tests.

**M6 — Source provenance.**
The crate lives in its own repository, `CoNET-project/bridgeAAC`, and the
release binary is built from a tag on `main`. Build outputs are ignored
(`/target`, `/artifacts`, `/build/`).

## Reproducible release build

- `rust-toolchain.toml` pins `1.99.1`.
- `scripts/shadow-release.sh` and `.github/workflows/release-aac.yml` set
  `RUSTFLAGS="--remap-path-prefix=<checkout>=/build --remap-path-prefix=<cargo home>=/cargo"`.
- Check: the same commit built at two different paths on the release host gave
  the same SHA-256 (`b29eee46…` for the pre-release commit), and the 0.33.12
  rebuild from the tag matched CI (`465bbfb9…`).

Before the pin, the host build (rustc 1.99.0, build path embedded) and the CI
build (rustc 1.99.1) differed. The difference came from the toolchain and the
embedded build paths, not from the CPU or the operating system.

## Verification

- `cargo test --locked`: 69 library tests and the integration tests pass.
- Live (H1): the anchored Base block returns `final true` with the same state
  root as the previous production binary. A block behind the anchor returns
  `accepted no`. A forged `receiptsRoot` served by a proxy was accepted by the
  pre-fix binary (`final true`) and is rejected by the fixed binary
  (`DigestMismatch`).
- Live (M2): a non-existent requested hash returned `final true` before the
  fix and returns `accepted no` after it.
- Live (H2): `conet-consensus` against the beacons reports `genesis-pin yes`,
  `committee-handoff yes`, `aggregate-verify yes`, `signature-check yes`, and
  `trusted-committee no`.
- Shadow: `shadow-service --once` from a fresh cursor gives the same
  `receipts-root` and `decision none` as the previous binary, with the expected
  `cursor missing` alert.

## Open items

1. Four Base operations (`0x133f…`, `0x7374…`, `0x8508…`, `0xa15f…`) have been
   pending since before 0.33.11. They are reported as `reconcile pending` and
   need manual review. They are not caused by the fixes in this record.
2. The genesis constants have been checked against two beacons, but both are
   operated by the publishing operator. An independent source (a node outside
   that operator's identity table) is still needed before the pin counts as
   trusted. The H2 code fix is in place; the closure record should say this.
3. A full `forward-committee` run over one period was not completed. It fetches
   one block per slot.
4. The L1 path has no ancestry proof, so older Base blocks cannot be verified
   through the anchor.
5. The GitBook pages describing AAC are being updated separately.
